> 状态：**规划成稿待 owner 终审**；OpenSpec 未建，版本规划门未走完，不构成开工授权。
> 建立：2026-09-27（产品重对齐 D-20260927-014/015/016 之后）；两轮需求对齐已完成。

## 1. 产品背景（引用对齐结论，勿重复推导）

- 一句话：一个住在本地的常驻量化研究员——对话协作为主，Web 为看板与审批主界面，CLI 是 Agent 工具接口；终局全链路含实盘（最重人工闸门）。
- 核心价值顺序：策略级判断（"我的策略行不行"）先行，因子研究第二层。
- 阶段路线：0 地基（✅ 2026-09-27 审计修复）→ **1 策略判断闭环（本版本）** → 2 常驻研究员 → 3 持续观察 → 4 实盘。
- 完整决策见 `DECISIONS.md`。

## 2. 版本目标（2026-09-27 与 owner 两轮对齐后确定）

**v0.5.0 — 策略判断闭环**，单版本交付，不拆分（工具层单独成版只有 CLI 面，对 owner 是无效交付）。

**验收标准（核心）**：owner 在 Web 对话里问一个真实 R-breaker 策略，得到一张有用的结论卡，并在对话里完成至少一次调参重跑。

**已定事项**：
- 版本号 0.5.0；不拆分。
- 策略范围：只接 R-breaker 一种模板，把一个价值时刻做透；模板扩展留给后续版本。
- 对话入口：**Web 内嵌对话**，是必要开发而非可选项（owner 不使用 CLI；CLI 只作为 Agent 工具接口存在）。
- 结论卡：**保守详细版**——提案基础（结论档位、vs 持有对照、费后收益、胜率/盈亏比/回撤、分市场状态表现、换品种对照、可信度边界、下一步建议）之上，**增加参数邻域稳健性提示**：邻域参数（突破倍数 × ATR 周期小网格）结论不稳时，卡片明示"过拟合风险：邻近参数结论不一致"。
- 对话能力边界：**问答 + 调参重跑**（"换成 2.0 倍数""换 ETHUSDT 再跑""换 1h 周期"直接触发重跑出新卡）；注册策略等持久动作不在本版本。
- 审批中心：**后置到阶段 2**（届时随常驻 Agent 出现真实审批对象），v0.5.0 Web 骨架不为其占位。
- 默认数据：**首次提问自动拉齐** BTCUSDT/ETHUSDT/SOLUSDT 永续 90 天 1m；拉齐属长任务，必须有受理/执行中/完成的进度反馈。

**仍开放**（不影响产品需求，影响 design）：对话入口与 Agent 运行时的内部接线方式，依赖 §3 调研结论。

## 3. Agent 架构市场调研（2026-09-27）

> owner 指示：**调研不急于下结论**。本节是证据沉淀与初步分析，框架/架构选型保持开放，续调研后随 design 评审定稿。

### 3.1 调研对象概览

| 方案 | 形态 | 与 Kronos 目标形态的关系 |
|---|---|---|
| TradingAgents（Tauric Research，~109k star） | 按需决策的多 agent"交易室" | 覆盖"决策时刻"，不常驻、不执行 |
| RD-Agent(Q)（Microsoft，14.8k star，绑 Qlib） | 研究循环：假设→实现→回测反馈→进化 | Kronos 路线图原始出处；覆盖"研究循环"，不常驻不管执行 |
| ai-hedge-fund（virattt） | 人格化投资大师 agent 团队模拟 | 教学/演示向，无执行 |
| Freqtrade / FreqAI（生产级 OSS 机器人） | 常驻 bot + dry-run 模拟盘 + Telegram 远程控制 | 覆盖"常驻 + 持续观察 + 聊天控制"，无 LLM 无研究 |
| FinRobot / FinGPT（AI4Finance） | 金融 agent 平台框架 | 学术向，印证"库→agent 平台"趋势，无可直接搬用件 |

初步判断（待验证）：市面无现成方案同时覆盖"常驻研究员 + 研究循环 + 安全闸门 + 全链路"；最接近的两个各占一半（RD-Agent(Q) 管 Research，Freqtrade 管常驻与执行）。

### 3.2 各方案要点

**TradingAgents**（github.com/TauricResearch/TradingAgents）
- 角色结构：分析师团队（基本面/情绪/新闻/技术）→ 多空研究员辩论 → 交易员 → 风控团队 → 组合经理审批。
- 触发方式：`.propagate(ticker, date)` 一次性出决策——按需，非常驻。
- 记忆机制：决策日志常开；后续运行取回**已实现收益与基准 alpha**，生成反思段落注入后续决策 prompt；可选 checkpoint 断点续跑。
- 明确研究用途，无执行；LLM 非确定性被列为已知限制。

**RD-Agent(Q)**（github.com/microsoft/RD-Agent）
- R/D 两段循环：Research 提出想法 → Development 实现为可运行代码 → 执行反馈进化；量化场景因子与模型交替优化。
- 成本结构：强模型管 Research、便宜模型管 Development，宣称完整循环 <$10。
- 终止机制：文档未见显式迭代上限/预算，由用户界定——Kronos 的预算制设计更严格。
- 工程：绑 Qlib；Docker 执行（Linux-only）；LiteLLM 多后端（含 DeepSeek）。

**ai-hedge-fund**（github.com/virattt/ai-hedge-fund）：投资人哲学编码进 agent 人格；教育模拟向。

**Freqtrade / FreqAI**（freqtrade.io）
- 常驻单进程 bot；**dry-run 与 live 同一条代码路径**（仅订单路由不同）。
- Telegram 作为控制面：启停、强制进出、状态查询——聊天式控制在生产验证多年。
- FreqAI 独立线程训练，不阻塞主循环。Kronos 已有 `freqtrade_bridge` 交叉验证目标。

**FinRobot / FinGPT**（arXiv:2405.14767）：开源金融 LLM agent 平台，趋势证据。

### 3.3 初步建议（未定稿）

待借鉴设计（进入阶段 2 规划的候选需求）：
1. **决策时刻角色分离**（TradingAgents）：分析→辩论（可选）→风险检查（确定性）→提议。
2. **反思记忆闭环**（TradingAgents）：决策后回看真实收益再反思；完整形态依赖阶段 3。
3. **dry-run/实盘同代码路径**（Freqtrade）。
4. **对话包含控制谓词**（Freqtrade Telegram）。
5. **模型分层省钱**（RD-Agent）：Kronos roles.py 已有 pro/flash 分层。

架构倾向（待评审）："常驻的是不花 token 的调度器，LLM 只在判断点唤醒"+ 上述借鉴件，在现有骨架上薄层实现；不整体引入通用框架。**保持开放**：若 RD-Agent(Q) 循环实现可拆用，评估部分移植。

## 4. Scope（草案，随 design 细化）

**工具层（确定性，Agent 可调用）**
1. 策略回测工具：R-breaker 策略配置 → 组合回测（复用 `research/backtest` 引擎，本版本将其首次接入产品路径）→ 结论卡数据结构（JSON schema）。
2. 结论卡生成器：确定性生成全部字段——结论档位（观察/改造/放弃）、vs 持有对照、费后收益、胜率/盈亏比/回撤、分市场状态表现、换品种对照、**参数邻域稳健性**、可信度边界、下一步建议。
3. 参数邻域扫描：固定小网格（volatility_multiplier × atr_period），判定邻域结论一致性。
4. 数据自动拉齐：首次提问检测并补齐 3 币种 90 天 1m（复用已修复的限速/容错同步）。
5. Agent 工具接口：上述能力注册进 agent 工具白名单（CLI 层输出 JSON，供脚本/agent 调用）。

**对话面（Web）**
6. Web 内嵌对话入口：后端会话管理 + 前端对话组件。
7. 意图解析：问结论 / 调参重跑两类意图；确定性解析优先，LLM 仅辅助解析自然语言参数，解析结果需回显确认。
8. 结论卡渲染组件（Web）。
9. 长任务进度反馈：受理 / 执行中 / 完成 / 失败四态（数据拉齐与重跑期间必须可见）。

## 5. 非目标（本版本明确不做）

- 多策略模板（只 R-breaker；均线/RSI 等模板后续版本）。
- 常驻 Agent / 调度器 / 主动汇报（阶段 2）。
- 审批中心（阶段 2）。
- 持续观察 / testnet 下单 loop（阶段 3）。
- Web 全面视觉重构（只加对话区与结论卡，不动现有面板）。
- 对话内注册策略等持久动作。
- 引入通用 agent 框架（选型仍开放，但本版本架构不依赖它）。

## 6. 风险

1. **对话↔运行时接线未定**（依赖 §3 调研）→ 缓解：对话面先接"确定性意图解析 + 工具调用"，LLM 只做参数解析与措辞，架构不强绑任何框架。
2. **回测引擎首次产品化暴露语义问题**（审计 FSR-005 已修重叠/覆写，FSR-006 因子指标语义统一仍是延后项）→ 缓解：结论卡数字口径以组合回测引擎为准并在卡上注明；FSR-006 不阻塞本版本。
3. **首次数据拉齐耗时**（节流后 3 币 90 天 1m 为分钟级）→ 进度反馈必须做好；失败要有明确重试路径。
4. **LLM 解析调参出错** → 解析结果回显确认后才执行重跑。
5. **Web 骨架范围蔓延** → 非目标清单硬约束，评审对照。

## 7. 测试

- 单元：结论卡生成器（给定引擎输出 → 卡片字段断言）、参数邻域一致性判定、意图解析（确定性部分）。
- 集成：对话端到端（mock LLM）→ 意图 → 工具调用 → 卡片 API；数据自动拉齐（mock 网络 + 真实 schema 校验）。
- 验收（人工，owner 参与）：真实提问 → 有用结论卡 → 一次调参重跑出新卡。
- 常规：覆盖率 ≥80%，ruff/mypy/CI 绿；涉凭证测试隔离不变。

## 8. 完成标准

1. owner 在 Web 对话完成"问结论 → 追问调参 → 新卡"全流程且判定有用。
2. 结论卡每个数字可溯源到引擎 artifact（本地文件留档）。
3. 首次提问自动拉齐数据，全程有进度反馈，失败可重试。
4. 全部价值面在 Web 对话内可达，无 CLI-only 交付。
5. 测试 / 覆盖率 / CI 达标。
